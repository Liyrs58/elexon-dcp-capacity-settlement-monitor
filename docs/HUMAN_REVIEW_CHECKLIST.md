# Human review checklist

Use this checklist before showing the project or using a figure in an interview.

## Evidence

1. Is the claim public, synthetic, inferred or unknown?
2. Is the source recorded in `docs/evidence-register.md`?
3. Does the Circular actually support the wording?
4. Have I avoided inventing a DCP database, server, CPU, API or architecture explanation?

## Data

1. Did validation pass?
2. Are the reporting window and units clear?
3. Do actual and received counts agree?
4. Does the backlog roll forward?
5. Do Python and SQL totals reconcile?

## Analysis

1. Is the threshold labelled synthetic?
2. Is the result descriptive, predictive or prescriptive?
3. Does each hypothesis have a limitation and next check?
4. Does the scenario state its assumptions?
5. Have I avoided calling a correlation a root cause?

## Communication

1. Is the customer impact confirmed or still a question?
2. Is the owner named by role rather than invented person?
3. Is the next update time agreed before sending?
4. Is the note clearly marked as a demonstration until real evidence replaces it?

## Interview honesty

1. Can I explain the key metric in one sentence?
2. Can I trace one chart from generator to browser?
3. Can I explain what AI tools did and what I owned?
4. Can I name one thing the project cannot know?
